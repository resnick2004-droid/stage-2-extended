## 3. Findings

### c2-1 — MATERIAL (F1 incomplete): `calendar_sha256` is never checked against `W.calendar_digest(starts)`

- **Where:** `extended/h4_collect.py:189-191, 207-220`
- **Evidence:**
  - Lines 189–191 only verify format (`isinstance(cal_sha, str) and _HEX64.fullmatch(cal_sha)`). After `starts` is validated at lines 207–212, `cal_sha` is never compared to `W.calendar_digest(starts)` and is dropped before `return`.
  - Synthetic probe 1 on an existing valid CSV confirmed `w42_readings` **accepts** both:
    - `params["calendar_sha256"] = "0" * 64`;
    - `params["calendar_sha256"] = W.calendar_digest(("2020-01-02",))` (digest of a different start list than the 4-day `starts`).
  - This leaves part of c1 F1 (`W42_H4COLLECT_c1_2026-11-22.md:45, 53`) unfixed. While `wave42.setting_rule` checks `calendar_sha256` against the search calendar when called via `wave42_apply.py`, standalone callers of `h4_collect.w42_readings` receive unverified `calendar_sha256` bindings, and `h4_collect.py` is frozen in `IMPORTED_FILES` once W42-R1 is pinned.
- **Remedy:** After line 212 in `_validate_sidecar_parameters`, add:
  ```python
  want_cal_sha = W.calendar_digest(starts)
  if cal_sha != want_cal_sha:
      raise _refuse(f"sidecar calendar_sha256 {cal_sha[:12]}... does not match starts digest {want_cal_sha[:12]}...")
  ```
  Add `("calendar_sha256", "0" * 64)` to `tests/test_h4_collect.py` (with `match=`, per c2-2).

### c2-2 — MATERIAL (F1 bug + masked test): `denial=False` is silently accepted, and `test_f1` falsely passed by catching `"collection CSV not found"`

- **Where:** `extended/h4_collect.py:175-181` (vs `extended/wave42.py:47`) and `tests/test_h4_collect.py:93-119`
- **Evidence:**
  - `extended/wave42.py:47` declares `VERDICT = {"denial": 0.0, "placement": "off", "focused_trader": "off"}` — `W.VERDICT["denial"]` is a `float` (`0.0`), not an `int`.
  - `extended/h4_collect.py:177` checks `if isinstance(vwant, int):`, which is `False` for `0.0` (dead code). Execution therefore enters `elif vgot != vwant:` at line 180; because `False == 0.0` is `True` in Python, `params["denial"] = False` passes `_validate_sidecar_parameters` without raising.
  - Synthetic probe 1 confirmed `w42_readings(csv_path, s)` **accepts** `params["denial"] = False` on a real CSV.
  - Synthetic probe 2 confirmed why `tests/test_h4_collect.py:102` (`("denial", False)`) still passed: lines 118–119 pass `tmp_path / "does_not_exist.csv"` with bare `pytest.raises(HC.H4CollectRefused)` and no `match=`. For `("denial", False)`, `w42_readings` fell through `_validate_sidecar_parameters` and raised `H4CollectRefused("h4_collect refuses its input: collection CSV not found: ...")`. That test design would pass all 17 cases even if every check in `_validate_sidecar_parameters` were deleted.
- **Remedy:**
  - In `extended/h4_collect.py:175-181`, check numeric verdict settings against `(int, float)` while excluding `bool`:
    ```python
    for vk, vwant in W.VERDICT.items():
        vgot = params[vk]
        if isinstance(vwant, (int, float)) and not isinstance(vwant, bool):
            if not isinstance(vgot, (int, float)) or isinstance(vgot, bool) or vgot != vwant:
                raise _refuse(f"sidecar verdict setting {vk!r} must be {vwant!r}, got {vgot!r}")
        elif vgot != vwant:
            raise _refuse(f"sidecar verdict setting {vk!r} must be {vwant!r}, got {vgot!r}")
    ```
    (Also update docstring line 14 from `denial == 0` to `denial == 0.0` for consistency with `wave42.VERDICT`.)
  - In `tests/test_h4_collect.py:93-119`, include an expected `match` regex per parametrized case (never matching `"not found"`), and/or assert against both a nonexistent path (verifying `"not found" not in str(exc.value)`) and an existing valid CSV.

### c2-3 — MINOR (F4): `path.read_bytes()` does not wrap `OSError` in `H4CollectRefused`

- **Where:** `extended/h4_collect.py:230`
- **Evidence:** Synthetic probe 6 patched `Path.read_bytes` to raise `PermissionError("denied")`; `w42_readings` leaked raw `PermissionError` instead of raising `H4CollectRefused` (as suggested in c1 F4's remedy and line 11 "failing closed with `H4CollectRefused`").
- **Remedy:** Wrap `raw_bytes = path.read_bytes()` in `try ... except OSError as exc: raise _refuse(f"cannot read collection CSV {path}: {exc}") from exc`.

### c2-4 — MINOR (F6): Missing `match=` on `test_f3_refuses_invalid_starts` and a few remaining refusal-path test omissions

- **Where:** `tests/test_h4_collect.py:162-177, 198-254`
- **Evidence:**
  - `test_f3_refuses_invalid_starts` (`:162-177`) uses bare `pytest.raises(HC.H4CollectRefused)` against a real CSV whose start dates are `2020-01-02..2020-01-06`. If ISO-date validation were regressed on e.g. `["2020-99-99"]`, `w42_readings` would still raise `"start '2020-01-02' not in sidecar starts"` downstream and the test would still pass.
  - No explicit test covers: `csv.Error` wrapping (e.g. `csv.field_size_limit`), short ragged rows (only long ragged row is tested at `:222-225`), header-only CSV, `rows_from_readings` refusing wrong `reading`, or `extra_keys` round-trip.
- **Remedy:** Add `match=` patterns to `test_f3_refuses_invalid_starts` (and/or test against a nonexistent CSV excluding `"not found"`), and add compact assertions for `csv.Error`, short ragged row, header-only CSV, `rows_from_readings` wrong `reading`, and `extra_keys` round-trip.

### c2-5 — NOTE (F5): `rows_from_readings` silently casts complex arrays via `np.asarray(..., dtype=np.float64)`

- **Where:** `extended/h4_collect.py:132`
- **Evidence:** Synthetic probe 7 passed `np.full((4, 3), 1+2j)` into `rows_from_readings`; NumPy emitted a `ComplexWarning` and silently dropped the imaginary part instead of raising `TypeError`/`ValueError`. Unlikely in real pipelines (same behavior as `wave42.py:202`), but easily guarded with `if np.iscomplexobj(b.values[k]): raise _refuse(...)` if desired.
