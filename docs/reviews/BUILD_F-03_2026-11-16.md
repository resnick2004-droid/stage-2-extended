## The brief's questions

**1. Look-ahead.**
- **The states.** Every state is computed from bars stamped at or before m − 6, plus earlier sessions:
  - `LRS` and `DIS` at `last = m − 6`, from prefix maxima and minima taken from slot 0;
  - `rv60` over the bars stamped t − 60 .. t − 1, with t = m − 5;
  - the 20-session slot median, the 22-session HAR and M, and the 250-session share, each strictly over prior rows
    (`_prior_window` pads in front and never wraps).
- **u3's fit.** Each fold trains on the choice block before its test year, less the last 22 sessions. The out-of-fold
  forecasts and their 250-session reference use that fold's coefficients. The final fit forecasts only rows from
  2024-01-02 on. The label `y` never enters a regressor. There is no leak through the hold-out, the regressors or the
  final fit.
- **What T-2 and A3 can see.** Both can see a breach: an off-by-one at the alert, a forward window, or a fold trained
  on its own test year (each changes a visible row). Neither can see the final fit, because no synthetic frame reaches
  2024 and run 2 is unbuilt (hence M5's guard). A3 on real bars is incomplete (M3).
- **Judged-block outcomes before run 2.** None is read except inside A0, under `identity`, as the text sanctions.
  Run 1 reads the choice block, Q-83's dates, and the registered, disclosed inputs (P-16's shift, admitted marks and
  `mean_dv`). It also loads Stage 2's `user_journey.csv`, judged starts included, and compares only choice-block
  starts. Those rows are P-16's registered journeys, already read program-wide, and nothing of them reaches an
  output.

**2. The waiting class.**
- **The declines.** The wrapper declines an offer exactly when three things hold: the vendored draw would take it, the
  account has not traded and `days < W` at routing, and the offer's flag is False. Out-of-state offers include every
  label mark, the window marks and the report-day 07:35 offer, which section 8 drops. The router asks each account
  once per trade, after the cap, flat and opposite-side tests, so each decline is counted once. A first trade whose
  P&L is NaN leaves `trades` at 0 and the account still waiting, which is right.
- **Bit for bit.** With the state always on, or W = 0, `_gate` returns the vendored answer unchanged. The router uses
  the registered object only through `can_take`, `can_stretch`, `trade_dollars` and `hasattr`. Under forfeiture,
  `forfeit_over(C)` subclasses the waiting class without its own `__post_init__`, so the wrapper is still made.
- **The lookup.** It cannot misplace an offer on real data. A start's window is a contiguous slice of the same job's
  blocks (`blocks[s:s+L]`), so the true position is always among the hits. Two hits that differ in state refuse
  (`AmbiguousOffer`), and two that agree cannot be wrong. Per-session fingerprints do collide on real data (every
  empty session, such as FOMC days and early closes, has one fingerprint), but a whole window holds trading sessions
  of about 190 trades each. The only possible failures are loud ones, which could stop a run hours in. **A0 would catch
  neither a misplacement nor a refusal**, because it never calls the lookup. A1 item 5 would catch a misplacement once
  M2 is fixed. Remedy: m3's self-check.

**3. The statistics.** Checked line by line against the text:
- the clustered twin (7.1): a shift within each (year, kind), all marks together;
- C1 and C1-close: the nested `diff_stats` on centred y, and `placebo_selection_bound` beside;
- C2: `two_sample_bound` beside;

  - a* = the largest of (a) on 2021-2022, (b), and (d) on 2023's out-of-state offers of that selection;
  - 20,000 inner draws, at the same levels.
- What follows: if its rejection rate's interval lies wholly above nominal, the cell is closed and counted before stage
  B. If not, the cell stays, with the verdict sentence.
- The lead must still rule, before run 1: whether both shares are run when one is flagged, and which (share, level)
  closes the cell. The natural reading is both shares, and any (share, level) wholly above.

**The seed.** Section 16 has no row for the inner draws. It declares A10's key `[A10 seed, class, share, j]` and B2's
`[B2 seed, line, j]`. Two readings use only declared seeds:
- **(i) A10's replication key, extended by the inner index: `[A10 seed, class, share, j, i]`.** This is "the same A10
  replications", each with its own draws. It is the pattern the builder used for T-10 (`[test seed, 200, j, 0]` for
  the data and `[test seed, 200, j, 1, i]` for the inner draws). The selections stay independent, so the
  Clopper–Pearson count stays binomial. **Recommended.**
- (ii) B2's C1 key `[B2 seed, 0, i]`, shared across selections. This reuses stage C's first 20,000 C1 draws, and makes
  the 2,000 rejections dependent, which the interval does not allow for. **Not recommended.**

Reading (i) introduces no new literal and widens the A10 key's use only from the selection to the replication's draws.
Under E-097's practice (draws derived from declared seeds) it needs no new declaration, **provided the lead records it
in a decision row before run 1 starts**.

**Deciding after A10 has flagged would be a choice made after seeing a result.** A10's flag is an outcome reading: the
dispersion of the population's centred values under random selections. It names a class, and so the cells at stake,
and the consequence's open parts could then be set knowing which cell they would close. The stop branch also makes a
second run 1 likely. I reached this independently of E-107's note, and agree with it.

**The cost.**
- *Timing.* In the built code one B2 replicate at the split's size (about 250 sessions × 200 marks) takes about
  2.2 ms in this machine's scratch check. Done naively, as 2,000 selections × 20,000 draws, that is about 24 hours per
  (class, share). The builder is right about the naive computation.
- *An exact shortcut.* The larger-of rule can reject only where nominal `cons` rejects, since each member's critical
  value is at least its t. So B2 is needed only for selections that nominal `cons` rejects on 2023 at 5 %; the 1 %
  rejections are a subset, and both levels share one set of draws. With per-selection keys (reading (i)), skipping a
  selection changes no other selection's draws.
- *Result.* At a lax rate of 5-15 %, that is 100-300 of the 2,000 selections: about 1-4 hours per (class, share) at one
  worker, less if `b2_replicate_sums` is vectorised across replicates (no draw changes). That is the text's "CPU hours".
- *The same shortcut* cuts T-10 at its declared size to under an hour.

**Build it with:**
- a synthetic test that it closes a cell whose rule is lax and keeps one whose rule holds;
- a test that the shortcut equals the full computation on a small case;
- a test that the result does not depend on which selections are skipped.
