## 2. Blocking findings (MATERIAL; fix before the pin)

### B-1. The input is not bound to H4's one output, so the rule can be applied to a chosen subset, or twice, and the better result kept
- **Where:** declaration 1, lines 25-51 (what a reading carries), 54-65 (what is refused), 9, lines 283-288 ("computed
  from H4's result files"); `extended/wave42.py` 143-205 (`_validate`).
- **Evidence:** `_validate` checks the following and nothing else:
  - the block tag;
  - that start days fall inside 2020-01-02..2023-12-29;
  - that the four baselines are paired;
  - that there are at least two seeds;
  - shapes, blanks and ranges.

  It does not check that the start days are H4's declared starts, that the seeds are H4's declared seeds, that the
  matrices come from H4's result file (by its manifest's sha256), that the reading is the martingale-outcome reading,
  or which optional measures H4 declared. The probes confirm it:
  - the first half of the start days alone is accepted, and delta\* moves;
  - the first two seeds alone are accepted, and delta\* moves;
  - dropping `accounts_max` from every baseline turns its limit into "not set" (the rule's own test,
    `test_an_absent_optional_measure_sets_no_limit`).

  Nothing in the declaration says the rule is run once, from a clean checkout, on the whole of H4's output, with its
  output written through `write_result`. The pin covers the document only. `extended/wave42.py` can change after H4 is
  read while the pinned text stays the same.
- **The failure it allows:** after H4 is read, the rule can be run on, for example:
  - starts from 2021-2022 only;
  - 10 of H4's 50 seeds;
  - a reading without the workload columns.

  Each run gives a different B\*, set of caps, delta\* or set of limits, and the most convenient one can be pinned. Each
  of those runs is "the rule applied mechanically". The selection happens in the input.
- **Remedy:** the declaration states, and the code refuses otherwise:
  - The input is H4's result file(s), named by the sha256 in H4's manifest. The rule reads every start day and every
    seed H4 declared, and checks the start list and seed list against H4's declaration.
  - The optional measures present are exactly those H4's declaration lists.
  - The reading is tagged as the martingale-outcome reading (CHARTER 3.2) and refused otherwise.
  - The rule is run once, from a clean checkout of a named commit, and its output is written with a sidecar manifest.
    The pinning row cites that output's digest and `input_sha256`.
  - The pin covers `extended/wave42.py`'s sha256 as well as the document's.

### B-2. Sessions left: the declaration's source (MEASURES 1.1's obs) is refused by the code, and the horizon embargo trusts the caller
- **Where:** declaration line 29-30 ("its sessions left in its block (MEASURES 1.1's obs)"); `extended/wave42.py` 160-162
  (strictly decreasing required); MEASURES line 64 (`obs_u = min(252, ...)`); CHARTER 3.6 (d).
- **Evidence:**
  - MEASURES' obs is capped at 252, so every search-year start with 252 or more sessions left carries the same value. A
    probe passing the capped form is refused ("sessions left are positive and strictly decreasing"). The rule as
    declared therefore refuses H4's input in the form the declaration names.
  - Conversely, the rule never derives sessions left from the calendar. A probe that adds 300 to every start's sessions
    left, with finite values where a truncated run would write them, is accepted. Synthetic E_252 grows from 129 to all
    360 starts.
- **The failure it allows:**
  - Refusal of the declared form forces a change to the input format, or to the rule, after H4 is in hand. That is a
    change after a look.
  - An overstated or off-by-one sessions-left count silently admits starts whose 252-session outcome was cut at the
    block's end. Those truncated outcomes then shape the caps, B\* and the limits.
- **Remedy:**
  - The rule takes the pinned search calendar (a date list: arithmetic, not a result) and computes each start's
    sessions left itself, uncapped.
  - It refuses a start day not on that calendar.
  - The declaration says "uncapped" in place of "MEASURES 1.1's obs", and states whether the start session itself
    counts.

### B-3. J is an input, but J is set from the rule's own output, and the limits move with it
- **Where:** declaration 1, lines 48-52; 5.3, lines 203-206; 6 step 2, lines 228-231; 7's last row, line 260;
  `extended/wave42.py` 476 (`se_test` uses `J`); the three-way note 4.1, line 682 ("J, m set by 2.5's formulas so that
  power at delta\* reaches pi\*").
- **Evidence:**
  - The three-way note sets J after delta\* is known. The rule takes J as an input and outputs J_needed.
  - The limits' headroom value depends on J. With baselines equal on supply, the probe gives `taken_mean_p10` as 0.32367
    at J = 20, 0.32873 at J = 200 and 0.33033 at J = 2000, each binding at the headroom.
  - Section 7's row ("J raised: ... the budgets, weights and delta\* do not move") is silent on the limits, which do
    move.
- **The failure it allows:** the rule must be run at least twice: once for J_needed, then again at H3's J. Nothing says
  which run is pinned, or forbids choosing J (any J at or above J_needed) to place a headroom-bound limit where it
  suits.
- **Remedy:** declare the sequence. Either:
  - (a) J is H3's declared number, fixed before H4 is read, and the rule is run once with it. If J_needed exceeds J, the
    gate fails, with no re-run at a larger J. Or:
  - (b) the rule sets J itself (say J = J_needed, or the smallest multiple of a declared m at or above it) and uses that
    J in the headroom. J then leaves the inputs.

  Add the limits to section 7's J row.

### B-4. The redundancy drop measures co-movement across users within a design, which is the wrong axis for a composite that ranks designs
- **Where:** declaration 4.3 step 1, lines 148-152; `REDUNDANT_RHO`, line 87; `extended/wave42.py` 376-395. CHARTER
  3.9, lines 403-407, says it outright: with four baselines, "the dimensions come from variation across start days and
  seeds, not across designs".
- **Evidence:**
  - Spearman's rho is computed over pooled units, `(s, c)` of the four baselines.
  - Under Topstep's verified fees (`vendor/stage2/config/rules.yaml` 465-489: $49 a month on the standard path, a $149
    activation), a one-Combine plan's cash to the first pass grows with the months it takes to pass. So, within a
    baseline, `cash_to_first_pass` is close to a monotone function of the time to pass, and that time is most of the
    time to the first payout.
  - The rule's own test `test_a_redundant_dimension_is_dropped_and_the_weights_reset` shows the drop firing on exactly
    such a monotone relation.
- **The failure it allows:**
  - Within-baseline speed and cost come out at rho of 0.9 or more, so `cost` is dropped.
  - The survey's designs then trade them off across designs: a design that buys three Combines at once passes sooner
    and pays three subscriptions. The composite credits its speed at no cost to its cost score; only P_B and ruin at B\*
    see the spending.
  - The drop also re-ranks the ROC weights. Over the same order, D = 6 gives (0.408, 0.242, 0.158, 0.103, 0.061, 0.028)
    and D = 5 gives (0.457, 0.257, 0.157, 0.090, 0.040). H4's data therefore move money's weight and every later
    dimension's.
- **Remedy:** remove the data-driven drop. The declaration has already avoided MEASURES 3's aliases a priori (4.1, lines
  120-122), which is what m-4 asks for, and m-4's concern is a loading-based reduction, not fixed weights.
  - Keep the six dimensions and their weights as declared.
  - Report the rho matrix beside, deciding nothing.
  - Redefine the fallback's trigger without the drop: for example, a dimension constant over the pooled units, or never
    (CHARTER 3.9's fallback is for "the weights cannot be set").

  If the lead keeps a drop, it must not apply to a pair that the objective names separately ("fastest and cheapest").

### B-5. The cost dimension's never-blank form rewards not passing
- **Where:** declaration line 42 (`cash_to_first_pass`: "the all-units form, censored at W + 1"), line 130 (cost, lower
  is better); MEASURES (2), lines 347-351 (an unpassed unit's value is `spent_before(rel_u, W + 1)`, a censored lower
  bound); MEASURES 1.3, lines 136-143 (the pinning row may pin a never-blank form).
- **Evidence:**
  - For an unpassed unit the value is what it has spent so far. A unit that fails its one $49 Combine in the first
    month and buys no other (a design with a purchase cap of one, say) scores x = 49.
  - A unit that passes in its second month scores 98.
  - The composite, a mean over E_W of the clipped, lower-is-better z, ranks the non-passer as cheaper.
- **The failure it allows:**
  - A design that trades little and rarely passes collects up to the cost weight (0.103 at D = 6) for spending little.
  - Together with bankroll (25) and ruin (24), which also favour spending little, about 0.37 of the composite's weight
    can favour inactivity. Only money, speed and steady oppose it.
  - The survey's surrogate optimises this composite, so it will look for such designs.
- **Remedy:** pin a never-blank form that does not reward censoring:
  - an unpassed unit takes the dimension's upper cap (z = 0); or
  - the dimension is the unconditional mean of "cash to the first pass, with unpassed units at hi_d".

  Both are admitted by 2.2 (a) as a clip in the definition. State the same check for ruin. There, an unpaid unit within
  B\* counts as not run out, which is MEASURES (24)'s "censored" state. The limit `not_paid_within_B` covers it, so it
  is acceptable, but say so.

## 3. Minor findings (fix in the same revision; none changes a mechanism unless stated)

### m-1 (MATERIAL). The ROC order is asserted as "CHARTER 2's objective order", but CHARTER 2 lists the terms without ranking them
- **Where:** declaration 4.1, lines 114-118; 4.3 step 2, lines 153-155; CHARTER 2, lines 24-26.
- **Evidence:**
  - CHARTER 2's sentence lists the terms. It ranks nothing, and no row records the operator ranking them.
  - ROC turns that order into weights 0.408 / 0.242 / 0.158 / 0.103 / 0.061 / 0.028. "Least ruin", which is named
    in the objective, gets under 3 %, and steady income about 6 %.
  - Can ROC hand one dimension the result? Not by itself. Money is a plurality (0.41, rising to 0.52 if two dimensions
    drop), not a majority. Its effective weight is w times the between-design spread of mean z, which H4 cannot show
    (four baselines).
- **The failure it allows:** a choice that carries the money is presented as fixed by an outside source.
- **Remedy:**
  - Either relabel the order as the lead's ranking under E-221, a fixed choice with its reason, and print the weight
    table, with w_d / (hi_d - lo_d) per dollar and per session, as CLAUDE.md asks for every parameter.
  - Or use equal weights, the other standard rule for criteria with no ranking information.

### m-2 (MATERIAL). delta\*: "resolved" is not a 95 % band at small H4 seed counts, the value jumps, and a large delta\* makes the gate toothless
- **Where:** declaration 5.1, lines 171-180; `RESOLVE_Z`, line 88; `DELTA_MIN`, line 90; `extended/wave42.py` 156
  (two seeds accepted), 411-424.
- **Evidence:**
  - At nJ H4 seeds, g / se is a t with nJ - 1 degrees of freedom. The chance that a zero-mean gap is called resolved is
    0.148 at nJ = 2, 0.058 at 5 and 0.027 at 30. Adjacent gaps are taken after ranking, so they are non-negative by
    selection.
  - delta\* is the minimum over a set that changes membership at a threshold, so it jumps. If a borderline gap of 0.012
    falls out of the resolved set, delta\* can move to the next resolved gap, say 0.05, a factor of 17 in the J the gate
    needs.
  - At the floor of 0.01 and k = 13 (alpha 2.75e-4, c_h 4.05), 2.5's one-horizon formula needs 185,082 to 239,243
    units, for sigma from 0.3 to 1. At 580 held-out starts that is about 319 to 412 seeds: demanding but not impossible.
  - The opposite case: few H4 seeds leave the three Stage 2 baselines unresolved while the coin's large gap is resolved.
    delta\* is then that large gap, and the gate is passed at a size no realistic design reaches. That is the toothless
    case.
  - The floor of 0.01 is a typed judgement ("below which no user would change design") with no source.
- **Remedy:**
  - Refuse H4 readings with fewer than a declared seed count (for example 30), or use the t quantile at nJ - 1.
  - Cap delta\* from above. For example, delta\* is at most the gap between the top two baselines when that gap is
    resolved, otherwise at most DELTA_FRACTION x spread. Or declare that a delta\* above a stated value is reported and
    the gate held at that value.
  - Label DELTA_MIN as the lead's choice and translate it into dollars and sessions through the weights.

## 4. Notes (no change needed; recorded)

- **n-1.** Best-pair sigma uses the disjoint-seed form (sqrt(2) x the best baseline's within-day sd): conservative.
  sigma^2 Q is an approximation for a multi-horizon composite (the per-unit composite is weighted by w_d, but Q by
  w_d / n_{h_d}). The forecast decides nothing; H3-D decides (declaration line 205).
- **n-2.** Spearman on heavily tied dimensions can rarely reach 0.9. P_B takes values in {0, 1/3, 2/3, 1}, ruin is
  binary, and speed has a mass at W + 1. That matters only if B-4 keeps the drop.
- **n-3.** B\* is pooled over the four baselines, the naive coin included. If the coin's spending tail is the longest,
  B\* is set by it, which loosens the bankroll stop for every design. This is declared (10.1) and reported. The
  alternative is the best baseline's median.
