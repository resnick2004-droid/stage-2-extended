## Findings

### MINOR-1: no test fixes T for a trade bound by the 15:10 flatten

- **Where:** `extended/three_way_s1.py` l.162 and l.171-172 (the code is correct); `tests/test_three_way_runner.py` l.982
  (`test_s_c_the_walk_never_reads_the_realised_exit`).
- **Evidence:** the s-c test uses `time_limit = 90.5`, entry 1000 and `SESSION_END` 1330. The time limit therefore binds,
  and `limit = min(time_limit, SESSION_END - entry)` is never tested on its second term. I built a scratch mutant that
  replaces `limit` with `float(p.time_limit)` in both the `walk_step` and the `walk_steps` call. It passed all 10
  S1/walk/flatten tests of `test_three_way_runner.py`: the s-c test, `test_n2_s1_holds_the_flatten_and_the_flat_gap`,
  the rb1/m4/b2 tests, the antithetic and exact-centre tests, and the S1-through-runner test.
- **Failure it allows:** a regression that sets T to the time limit for a `flatten` trade (one entering 40 minutes before
  15:10 under a 90-minute limit) would walk 90 minutes of variance instead of 40. That overstates the walk's barrier
  hits, and no test would fail.
- **Remedy:** add a case with an entry less than `time_limit` before `SESSION_END`. Assert that `(walk_step, walk_n)`
  equal the values for `SESSION_END - entry`, and add the mutant (call it SCt) to the table.

### MINOR-2: the 1e-3 tolerance holds only at the two tested points. The general residual is about 1.2e-3, and it comes from the lattice, not from leaving it

- **Where:** `tests/test_three_way_redraw.py` l.229-247 (`tol = 1e-3`, and the docstring "agrees ... within a tolerance
  of 1e-3"); the draft's s-c row (`prereg/DRAFT_H3_three_way.md` l.557: "a 37 / 55 bracket against the one-tick lattice").
- **Evidence (my own code; it imports nothing of the build's walk; scratchpad `indep_walk*.py`):**
  - At the tested points my code agrees with the build. At T 90 (s 3, n 640), coarse minus fine is -2.8e-5 and the
    rounded barriers (54/36) give +5.3e-3. At T 30 (s 2, n 480), coarse minus fine is -3.3e-4 and the rounded barriers
    (56/36) give +1.3e-2. The tolerance does sit between the two at both points, as claimed.
  - In exact fractions at the coarsest n the bracket admits (s 3, n 455, sigma sqrt T = 64.00001), gross = 0 exactly.
    P(stop) is 0.542233 against 0.542123 on the one-tick lattice.
  - Over sigma sqrt T in 32-40 on 37/55, at the coarsest n just after s steps up to 2:
    - sigma sqrt T 32.4 (n 262): |coarse - fine| = 1.16e-3.
    - sigma sqrt T 33.6 (n 282): |coarse - fine| = 1.08e-3.
    - The largest gap from Brownian motion's exact P(stop), from the eigen-series, is 1.12e-3.
  - The build's `walk_law` gives the same values as my code to 7 digits (0.2699343 at 33.6).
  - **The cause is the lattice, not the off-lattice sub-step.** The on-lattice brackets 36/54 and 36/56, walked at the
    same (s, n), are 1.23e-3 from Brownian motion. So the off-lattice law is no worse than the old divisor rule's law
    at that resolution. The residual is simply the price of WALK_MAX = 1024: n can fall to about 256 when s >= 2.
- **Failure it allows:** no wrong output from the code. A reader could take the docstring and the draft row as a
  general bound of 1e-3 on P(stop). The real residual is about 1.2e-3 absolute, about 0.5 % relative. The gross is still
  zero exactly, so the zero-edge expectation is unaffected. The split between barrier exits and time exits moves very
  slightly, and by different amounts for different brackets.
- **Remedy:** reword the docstring to "at these two points". State beside H3's walk row that the lattice's
  discretisation residual at n >= 256 is about 1e-3 in P(stop), measured, the same on or off the lattice. Optionally,
  add a declared sweep with a tolerance of 2e-3 against the Brownian series.

### NOTE-1: the epsilon departs from the literal ceil in a window too small to matter

`extended/three_way_redraw.py` l.160 computes `ceil(x - 1e-12)` with x = sigma sqrt(T) / 32. When x lies in (k, k + 1e-12],
the code takes s = k where the literal rule takes k + 1. In that window sigma^2 T / k^2 <= 1024 (1 + 2e-12 / k), which
rounds to 1024, so n never exceeds the cap. I found no violation in 200,000 random (sigma, T) pairs, and at
mathematically integer x (32k at T 1, 8k at T 16, k 32 / sqrt(90) at T 90, k 32 / sqrt(37.3)) the code gives s = k and
n = 1024 for k in {1, 2, 3, 7, 13, 100}. For x >= 8192 the epsilon falls below an ulp and does nothing. A rounding error
upward then gives s = k + 1 and n < 1024, which is still within the cap. The guard is sound. The draft row states the
bare ceil, so a phrase there ("computed with a 1e-12 guard against floating error") would make it match the code.

### NOTE-3: H3-D's `news` and `other` exits will need their T stated

## What I checked that found nothing

- **The rule.** `walk_step` is `max(1, ceil(sigma sqrt(T) / sqrt(walk_max)))`. `max(1, ...)` is redundant, because
  ceil of a positive number is >= 1, and harmless. All eight of the test's cases check out by hand (for example
  20·20/32 = 12.5 gives 13, and 32·sqrt(1.0001)/32 gives 2).
- **Where T comes from.** `three_way_s1.py` l.162: `limit = min(float(p.time_limit), float(SESSION_END - entry))`. Both
  calls at l.171-172 pass `limit`. `ex` and `dur` feed only the trade's exit field. SCx and SCn kill the
  realised-exit forms. In the journey, `_trade_mc` and `_trade_dp` read `walk_step`, `walk_n`, g, l and costs, and never
  `t.exit` (the s-c test's t1 and t2 also show it). `t.exit` is read only by the schedule's one-position overlap check.
- **The off-lattice law.** My own derivation in fractions: the last interior point on each side moves to the barrier or
  one step back with p_up = d_dn / (d_up + d_dn). That is identical to `_p_up`'s three cases, including the race
  L / (G + L) when both barriers lie within one step. gross = 0 exactly at (s 3, n 640), (s 2, n 480) and (s 3, n 455).
  Time exits lie strictly inside (-L, G), since d s < L and u s < G, so the flatten clip's bound "at most x_flat - x_stop"
  still holds.
- **No refusal, no runaway.** `walk_barriers` now refuses only a non-positive s, l or g. The `Trade` refusal (rn-2,
  walk_n > 1024) can no longer fire from S1, because n <= 1024 holds for every pair (proved above, and in 200,000
  random draws). A barrier closer than one step (s > l or s > g) gives d = 0 or u = 0 with rho = the barrier: a valid
  two-point move. Each walk is bounded by n, so no path runs forever. `SNAP` (1e-9) only matters when l / s lies within
  1e-9 of an integer, and an integer l with s < 1e9 never does.
- **The lane path off the lattice.** The existing lane-vs-scalar test (G = 2.75 by level, Lt fractional, s = 2) covers
  the float path's off-lattice handling on both sides. `check_walk_oracles` now includes s = 3 on brackets 4/6/8 by
  2/4/6, which are mostly off the lattice.
- **The mutants.** SCf (floor) fails at (6, 90) etc. SCr (divisor refusal restored) fails the 37/55/s=3 `walk_barriers`
  call. SCx and SCn fail at the 90.5 against 91 boundary. All four are killed and their identity controls survive.
- **`baselines_only`.** It has the same refusals as `paired` (exactly the four, no plant on a baseline), the same default
  `KeyGuard.sampled(plan.starts, plan.seed_indices)`, the same `_arms` loop and the same `beside`. The guard records and
  checks only, and changes no value. Each arm's `run` is independent. The matrices and fill failures are equal per
  baseline (test l.957-978). There is no design-convention check because there is no design arm, which is correct.
- **The seed block.** H4's `h4_tests` seed-09 against every 2026xxxx literal in `extended/`, `scripts/`, `prereg/`, `tests/`,
  `identity/`, `docs/plans/` and `DECISIONS.md`, and against every `range(...)` block: the nearest are RL3's declared seed block and
  H3's H3's declared seed block. No hit in `vendor/`. One derived seed is in reach: `lift_bound.fixed_b_critical`'s
  `20261913 + 1000 G + lags`, whose residues 914-917 mod 1000 never meet 400-409. The key form makes such a collision
  impossible in any case. The roles, statuses and spares match H4's draft table. `PARTS` values are unique.
- **`check_use`'s early return.** It is reached only after `kind in kinds`, and no role but `h4_tests` lists `test`
  (H3's `tests` role is `None` and returns earlier). A non-test role cannot draw a `test` key, and a `test` key has no
  part field, so without the return the part check would refuse every H4 test key. `issue` and `is_issued` short-circuit
  on unknown roles, so there is no `KeyError`.
- **The draft.** `test_h3_draft` holds the s-c phrases and the absence of the divisor rule. A grep finds no leftover
  divisor or `walk_step_for` text outside reviews.
