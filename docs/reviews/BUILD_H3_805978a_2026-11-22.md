## Verdict: PASS WITH MINORS

The diff does what its message says. Through `seed_key` and `key_matrix`, the tests' seed is refused in every declared
part. `FIELD_RULES` holds H4-S, H4-U and the smaller-J key on every row of every part. `smaller_j_rng` is the declared
key, and A3's histories cannot come from the H3-A histories' role. The pin grammar reads F, RD and H pins and no DRAFT
or TEMPLATE file. TN, FR and FM fail as they should, and their identity controls pass. I found no seed collision: no
two roles share a seed value, and within one role the part word and the tag keep keys apart. Nothing in the diff
reads data or touches an identity surface.

No finding changes a declared rule of H3-0 or H3-A. H3's runs draw their coins through `three_way_journey` ->
`fastkeys.coin_uniforms` -> `key_matrix`, which is checked. **Finding 1 is MATERIAL for H4, not for H3.** The field
rules this commit adds for H4-S can be bypassed through a public path that builds the same key. It should be fixed
before H4's build is pinned on these rules.

Tests at 805978a (`OMP_NUM_THREADS=1`, `-o addopts= -p no:cacheprovider`): `test_three_way_keys`, `_fastkeys`,
`_mutations` and `test_declarations_fixed` gave 160 passed. The broad suite (`_keys`, `_runner`, `_stats`, `_redraw`,
`_design`, `_mutations`, `test_h3_draft`) gave 243 passed.

## Findings (by severity)

### 1. MATERIAL (for H4; MINOR for H3): `triggers.coin_key` builds the three-way coin key with no provenance, role or field check

- **Where:** `extended/triggers.py:921-932` (`coin_key`), used by `coin_side` (`:946`) and by
  `components.schedule_day` (`extended/components.py:373`). Compare `extended/three_way_keys.py:81-86` and
  `extended/three_way_fastkeys.py:198-211`.
- **Evidence:** a synthetic check on 805978a. `K.Unit(issue("h4s_schedule_side"), H4-S, history 1, seed index 5,
  start 7).coin_key(...)` is refused ("only at history = 0"). `triggers.CoinUnit` with the same fields gives a key word
  for word equal to the refused layout, and `coin_side` returns a side. The same path also accepts the tests' seed in
  D1, and the D1 coin seed as a plain `int` (a value rebuilt from the issued seed, which `seed_key` refuses as
  unissued). `K.uniforms` and `F.uniforms` also accept any hand-built key list or matrix whose first word is a block
  seed.
- **Failure it allows:** suppose H4-S's schedule side, H4-B's readings or any later runner draws through
  `triggers.coin_side` or `components.schedule_day` with an issued H4 seed. Then a schedule-side draw at seed index or
  start other than 0, a tests'-seed draw in a run's part, or an unissued block value all go through silently. The rules
  this commit calls "enforced" (H4-S, H4-U) hold only on the K/F path. H4's draft does not name which code draws the
  schedule side.
- **Remedy:** in `triggers.coin_key`, refuse any seed with `three_way_seeds.in_block(unit.seed)`, or route it through
  `three_way_keys.seed_key`. That is one line; `three_way_seeds` imports nothing, so there is no import cycle. Add a
  test that `triggers.coin_key` refuses each issued block seed. For the raw readers, either refuse a block seed in the
  first word of `K.uniforms`/`F.uniforms` unless the key came from `seed_key`/`key_matrix` (a marked list or array
  type), or add a static test that no `extended/` module builds a key list itself. Re-run the identities after the
  `triggers.py` change: it only adds a refusal for block seeds, and P-14 and P-16 use none.

### 2. MINOR: the tests' seed is still open to a run at an undeclared part index, and through the `test` kind

- **Where:** `extended/three_way_seeds.py:189-193` (the `test` kind returns before any part check; an undeclared index
  returns early for the tests' role); `extended/three_way_runner.py:84-92` (`Plan.__post_init__` does not check the
  part or the role).
- **Evidence:** a synthetic check. `Plan(seed=issue("tests"), part=0)` and `part=15`, followed by
  `F.coin_uniforms(...)`, are accepted end to end. `seed_key(issue("tests"), "test", test=99, ...)` is accepted, an id
  outside `TEST_IDS`. The H3 text (section 15) says the build's tests use ids 11 to 23, but no check holds the id.
- **Failure it allows:** item 5 was meant to ensure "no run's report draws under the tests' seed" (the docstring at
  `three_way_seeds.py:104-108`). That holds only for declared part indices. A run configured with the tests' seed and
  an unlisted part, or a report rng drawn from the `test` kind (as `tests/test_three_way_redraw.py:165` does), is not
  refused.
- **Remedy:** in `Plan.__post_init__`, refuse a part not in `PARTS.values()`, and refuse the tests' role outside
  `PARTS["tests"]`. Optionally refuse the tests' seed's `test` kind at an id outside `TEST_IDS` and id 1. Add these as
  tests.

- **Remedy:** extend `test_gk5_the_tests_seed_draws_in_the_tests_part_only` (`tests/test_three_way_keys.py:265`) with

### 4. MINOR: H4-S's field rule leaves the draw kind free

- **Where:** `extended/three_way_seeds.py:140`.
- **Evidence:** H4's draft (section 15) describes the schedule-side seed as one *side* draw per (session, moment). The
  rule fixes history, seed index and start but not `draw_kind`. `Unit(issue("h4s_schedule_side"), H4-S, 0, 0, 0)` is
  accepted with RACE, WALK and MISSED (synthetic check).
- **Failure it allows:** a race, walk or missed-signal draw under the schedule's side seed. That stream would be read
  by a use the declaration does not give it, with no refusal.
- **Remedy:** add `"draw_kind": K.SIDE`, which is 1 (`three_way_seeds` imports nothing, so write the integer with a
  comment), to the H4-S rule, and add one refused case to `test_gk5_the_field_rules_...`.

### 5. MINOR: the pin grammar's coverage is unchecked, and H3-D's future file name may not match it

- **Where:** `tests/test_declarations_fixed.py:11` and `:24-31`.
- **Evidence:** the grammar is exact. It refuses DRAFT and TEMPLATE files, and D2 and D3 were killed. But it reads
  only the form "`path` sha256 `hash`". DECISIONS.md also uses "`path`, LF sha256 `hash`" and "at LF sha256" (by
  convention these are not pins). The test does not check that every pinnable file under `prereg/` has a pin. H3-D is
  to be "declared later in its own text" (H3 text, line 5), name unknown. A name like `prereg/H3-D_...md` or
  `prereg/H3D_...md` fails `H\d+_`, so its pin would be skipped silently. `[^`]*` also allows `/` and `..` after the
  prefix (contrived).
- **Remedy:** add a completeness test: every `prereg/*.md` that is not `DRAFT_*` or `TEMPLATE_*` has at least one
  `PIN` match in DECISIONS.md (on master). Widen the H alternative to `H\d+(?:-[A-Z]\d*)?_`, or fix H3-D's file name
  now. Refuse `..` in a pin path.

### 6. NOTE: the H3 text names the build commit, but the build files are not held equal to it

- **Where:** `tests/test_h3_draft.py` at f454d8d, `test_the_build_commit_is_named_and_reachable`.
- **Evidence:** the test checks that 805978a is an ancestor of HEAD and that the build files exist there. It does not

- **Failure it allows:** a later edit to a build file passes the test, and H3 runs code that is not the declared
  commit's, even though the text says "every row's code is that commit's".
- **Remedy:** assert `git diff --quiet 805978a HEAD -- <the build files>`, or record the commit in the run's manifest

### 7. NOTE: the field checks add about 10 to 20 % per coin key on the hot path, for every block seed

- **Where:** `extended/three_way_fastkeys.py:203-211`.
- **Evidence:** synthetic timing with the `h3a_coins` seed, part A1, one moment. `coin_uniforms` took 0.651 us per key
  at the parent and 0.772 us at 805978a (n = 4096), and 0.784 vs 0.860 us per key (n = 65536). The cost comes from
  `np.unique` on every column, which runs even for roles with no field rule. H3-0's probe measures the build commit's
  cost, so the sizes stay consistent, but the cost is avoidable.
- **Remedy (optional):** build the value sets only when `FIELD_RULES` has an entry for (role, kind, part).

### 8. NOTE: smaller-J's generator is the same stream on every call, and the order of its uses is not declared

- **Where:** `extended/three_way_h3a.py:95-100`.
- **Evidence:** two calls to `smaller_j_rng()` give the same draws (synthetic check). Nothing calls it yet; H3-A's
  report code is not in this commit. If the report makes a fresh generator per pool, every pool shares common random
  numbers. If it threads one generator through the pools, the result depends on their order.
- **Remedy:** state in the report's code which of the two it does, and the pools' order. A report that applies nothing
  needs no new row.

### 9. NOTE: smaller details

- `FIELD_RULES` is keyed by `SMALLER_J_REPORT["role"]` (`three_way_seeds.py:142`). A later literal entry for
  `"h3a_histories"` would silently replace it.
- No test checks that each rule's (kind, part) lies inside its role's `ROLE_USE` and that each field belongs to its
  kind. A misspelt part would leave a rule that is never reached.
- H4's block literals appear in `three_way_seeds.py` comments and in `tests/test_three_way_keys.py`. The literal scan
  (`tests/test_three_way_design.py:53`) covers H3's block only. The run-time refusal of an unissued value still holds.
- `RoleSeed` can be built with the module's private token. A forged seed with the true role and value is
  indistinguishable from an issued one, but one with a wrong role fails `is_issued`. That is harmless, and Python
  cannot prevent it.

## What I tried that found nothing

- **Seed collisions:** H3's and H4's blocks are disjoint, and every role has its own value (`test_h4s_block_...`). A
  key's first word is its role's seed, so two roles never share a stream. Within one role, the part word and the tag
  separate the kinds. No key is shorter than four words, so SeedSequence's zero padding cannot merge two keys.
  `PARTS` values are unique (tested), and H4-U at 14 is new and unused. The smaller-J key (H3-A histories, plant, A1,
  all zeros) is the only plant key that role can make in A1, and no plant key is drawn anywhere in the code at this
  commit. The H4-U keys (plant = start, replicate = seed index) are distinct per unit.
- **Field-rule bypass inside K/F:** the per-part loop uses the broadcast columns, so scalar fields are covered. A
  matrix with one bad row is refused (S2, S10 and FM killed). A mixed-part matrix is refused at its first run part
  (F1 killed). Kinds with no part (`test`) carry no rule.
- **Pin grammar:** DRAFT_H3, TEMPLATE and `H_x` are not read. F-, RD- and H3_ pins are.
- **Data:** the diff reads no bar, no atlas and no held-out or confirmation date. `test_declarations_fixed` reads
  DECISIONS.md and `prereg/` only.
- **Identity surfaces:** the diff touches nothing under `vendor/`, nor `extended/reader.py`, `extended/triggers.py`,
  `extended/components.py` or `identity/`. Between 805978a and wt-three's HEAD the build files are unchanged; only
  `lever_space.py` and `t7_forecast.py` changed, through the master merges.
