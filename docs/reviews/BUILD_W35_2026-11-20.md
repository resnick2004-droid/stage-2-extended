## Findings

### R-1 (CHANGES-A-CONCLUSION). The playbook can offer a coin's side, and a side that never cleared the no-harm floor

**Where:**
- `extended/playbook.py:577-578`: the alert compares `tr.side_source` with the string `"trigger"`.
- `:290-294`: the declaration's `side.source` must be the string `"trigger"`.
- `:253-255`, `:68`: `no_harm_row` must match the pattern `E-\d+$`.
- `:308-309`: `side_rule` only has to be non-blank.
- The library:
  - `extended/components.py:269-270`: `_trade_row`, the only producer of a `ScheduledTrade`, hard-codes
    `side_source="coin"`, and `side=int(ex.side)` comes from `T.coin_side`.
  - `extended/components.py:264-265`: RL3's fade or break is derived from that coin's order kind.
  - `extended/triggers.py:49-53`: "the coin chooses, per ticket, the fade limit ... or the break stop".
  - `triggers.py:291-292`: `Offer`, "No side: the coin sets it".

**Evidence** (`scratchpad/w35/probe1.py`). Each of these is ACCEPTED:
1. A `ScheduledTrade` with `side_source="coin"`, put through `dataclasses.replace(..., side_source="trigger")`. The
   alert prints the coin's draw as `Side SELL (short) -- with the breakout`.
2. A declaration whose `side_rule` is `"toss a fair coin"`.
3. `no_harm_row="E-0"`, and `row="E-99999999"`. Neither is a row of `DECISIONS.md`.

**What it allows.** No code path gives a "trigger's own side":
- The library has no trigger-side function, and every real trade refuses at `:577` unless it is relabelled.
- Relabelling a coin trade is enough to produce a fully "traced" alert that tells a user to take the coin's side and
  attributes it to the trigger.
- For an RL3 component the printed `(fade ticket)` or `(break ticket)` is the coin's choice by construction.
- A design whose side failed the no-harm floor, or was never read against it, gets a playbook if its declaration names
  any `E-n` string.

So CHARTER 3.5's "A trigger whose side fails the no-harm floor offers no playbook side; that design is not carried"
is not enforced. The commit's claim "a coin side refuses" holds only for the literal source string `"coin"`.

**Remedy.**
1. Give the library a trigger-side function per source:
   - P-14: the breakout's sign, which `Offer.tag` already carries as `brk30+` or `brk30-`.
   - RL3: a declared fade-or-break rule per level.
   - P-16: its declared rule.
2. Have the scheduler stamp `side_source="trigger"` only from that function. The alert then recomputes the side from
   the trade's tag or ticket and refuses on a mismatch.
3. Make the no-harm row a manifest-checked result file: the floor reading, search years, this design's id and the
   margin pinned in 3.9. The playbook reads its pass/fail cell and refuses when the floor failed or is absent. The row
   id must also exist in `DECISIONS.md`, as `triggers.decision_rows` already does for `H2_ROW`.
4. Make `side_rule` a key into a closed vocabulary bound to that function, not free words.
5. Add tests: a relabelled coin trade refuses; a failed-floor file refuses; a missing row refuses.

### R-2 (MATERIAL). The alert renders a trade that differs from the declaration in its window, last entry, latency, entry, price and account

**Where:** `extended/playbook.py:565-596`. The checks made are firm, account membership, component, source, side
source, side sign, bracket, instrument, `live - alert >= L`, order kind in `ORDER_WORDS`, and the limit price equal to
the fill price. The docstring at `:42-44` says a trade whose "latency differ[s] from the declaration" refuses.

**Evidence** (probe1). Each of these trades of `pm_brk` (window 1080-1260, P-14 limit, L = 3, pool `ts_b2`) is
ACCEPTED:

| Probe | What it breaks |
| --- | --- |
| `live` 1303 | past the component's last slot |
| `live` 1333 | past the firm's last new entry (1328) |
| `live` 103 | overnight, for an NY PM component |
| `live` 1160 after `alert` 1101 | 59 minutes, where P-14 goes live at j + L |
| `decision` 1000 with `alert` 1101 | the decision is not the alert |
| `order_kind="market"` | the component declares `entry: limit` |
| `order_kind="stop"`, `ticket_rule="break"` | on a P-14 component |
| `STOP at 1.0` | a stop's price is never checked (`:592-596`) |
| account `ts_a1` | outside the declared `by_component` pool |
| `flatten_slot` 1400 or 1200 | printed as "Flatten by 16:20 CT" or "13:00 CT" (`:618`), not the declaration's 1328 or a window start |
| `underlying="ES"` | the declaration's instrument is MNQ |

**What it allows.** The user is told to enter an order that the evaluation never ran:
- outside the scheduled windows, which breaks CHARTER 3.5's no-collision guarantee;
- after Topstep's last new entry;
- with a different entry type;
- with an unverified stop price;
- in an account the rotation lever did not choose, which defeats the rotation that E-221 calls the reason accounts
  alternate.

**Remedy.**
1. In `render_alert`, refuse unless:
   - `comp.first <= live <= comp.last`;
   - `live <= last_entry`;
   - `live == decision + L` for a timed trigger, and `live` equals the trigger's own live slot for a latency-free one;
   - `alert == decision` where the source sets it so;
   - `order_kind` is the one the trigger's `entry` gives (or `ticket_rule` is in {fade, break} for RL3);
   - a stop price is level ± one tick, which needs the offer's level on the trade;
   - `flatten_slot` is in {`execution.flatten`, the start of a window of `ctx`};
   - the account is in the component's pool under `by_component`;
   - `underlying` is the instrument's.
2. Add a mismatch test for each of these.

### R-3 (MATERIAL). Declared void rules are not applied to the alert: `prior_void` is ignored, and the alert asserts "the day is not void"

**Where:** `extended/playbook.py:552-558` checks only `ctx.void`, `ctx.fomc` and the declaration's dated list.
`DayContext.prior_void` (`triggers.py:265-277`) is never read. `short_overnight` and `prior_abbreviated` have no test
in the alert. `:619-620` prints "the day is not void".

**Evidence:**
- An `am_rl3` (`kind: pd`) trade on `DayContext(prior_void=True)` is ACCEPTED. The declaration lists
  `prior_abbreviated` ("no trade from a component that reads the previous day's levels") as a void rule.
- The alert also takes FOMC and void status on the caller's word. A `ctx` built with `fomc=False` on an FOMC date
  passes, because the alert never consults `day_calendar`.

**What it allows:** an alert on a day that the playbook's own "Void days" section tells the user not to trade, for the
very component the rule names.

**Remedy:**
1. Apply each declared void rule to the component it names. `prior_abbreviated` refuses a component whose trigger
   reads prior-day levels (RL3 `pd` and `pdc`) when `ctx.prior_void` is set. `short_overnight` refuses a component
   whose trigger reads overnight bars (`calendar_reads()`).
2. Rebuild the day's void and FOMC flags from `day_calendar` for `tr.date` and refuse a `ctx` that disagrees.
3. Add tests for both.

### R-4 (MATERIAL). Size into news: the caller's windows are trusted, a position open into a window passes, and size is never bounded

**Where:**

### R-6 (MATERIAL). "A manifest-checked result file" is an integrity check only

**Where:**
- `extended/playbook.py:409-419`.
- `extended/results.py:read_result(text=True)` verifies the sha256 only.

**Evidence** (`scratchpad/w35/probe2.py`). A file written with `exploratory=True`, `parameters={"design_id":
"SOME-OTHER-DESIGN", "as_traded": True}`, outside any clean run, has commit `unknown`. It is ACCEPTED, and the
playbook prints:
- `From the result file another_designs_journey.csv (commit unknown):`
- the ZERO_EDGE sentence ("measured with every trade's direction replaced by a fair coin"), although the file says it
  is as-traded.

The other gaps:
- `:419` defaults the commit to `""`.
- A `-dirty` commit is printed unmarked.
- **Path mismatch.** For a relative path, `read_result` verifies `RESULTS_DIR/<p>` but the manifest is read from
  `<cwd>/<p>.manifest.json`, so the printed commit can come from a different manifest than the one verified.
- The docstring's own example `Path("results/<journey summary>.csv")` resolves to `results/results/...` and fails.

**What it allows:** a figure from a file chosen after a look, from another design or from a dirty tree is printed as
the carried design's zero-edge expectation, against CLAUDE.md's rule that results are run once from a clean checkout
of a named commit.

**Remedy:**
1. Refuse unless the manifest has:
   - a clean-run provenance (`provenance.clean_run`);
   - `git_dirty is False` and a commit that is not `unknown`;
   - `exploratory is False`;
   - a `prereg_id` or parameter naming the design and the convention (zero-edge journey).
2. Have the ZERO_EDGE sentence come from that manifest field, not from a constant.
3. Resolve the path once and read both the CSV and the manifest from it.

## What I tried that found nothing

  in `playbook.py` itself.
- **No licensed price in the playbook page.** `render_playbook` prints trigger parameters, the RL3 kind and the
  cutoff slot. It prints no level and no price.
