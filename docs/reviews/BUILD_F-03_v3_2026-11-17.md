  - `atlas_a3.cached_walk`, by `pd.read_parquet`.
- **No escape.** Each looks up `pd.read_parquet` as a module attribute at call time. A search of `extended/`,

  `from pandas import read_parquet` and no other bound alias; `pq.read_schema` reads only the schema.

  holds only while no worker reads data (NOTE A).

  wrapper is identical to an unwrapped read, values and dtypes alike. A read that includes judged rows counts each
  judged row once (entered once per read; no double pass through the `read_table` wrapper in this pandas). The wrapper
  is entered on every read, as T-3 requires.

## 2. New findings

### MATERIAL (before run 2; neither blocks merge, A0 or run 1)

**W1. A refusal in the scorecard stage discards stage C's verdict.** `scripts/fo_opening.py`, `run2`: the
`choice_beside(...)` call and its `if cb_bad: return _refuse(...)`, after `ctx.authorise("stage_C_scorecard")`.
- *Evidence.* The choice-block beside runs inside the scorecard stage, and its refusals return before `jdf` is framed or
  written:
  - a fold hash that does not match;
  - the choice block's states, recomputed from the pinned fits, differing from run 1's `states_sha256`;
  - a lookup problem on a choice job;
  - `choice_problems` (the extra P against the card's).
  Any exception in the scorecard's 108 every-start replays (54 judged, 54 choice) does the same.
- *What it lets go wrong.* All four judged purposes would then be spent, and the CARRIED or CLOSED verdict, the lines,
  floors and beside readings would be lost. Recovering them needs a second run 2 under a `repeat` row, after the
  verdict was computed once.
- *Change.*
  1. Run the choice beside's refusing pre-checks at the start of run 2, before `stage_C_states` is authorised. Those
     are the fold hashes, the states-hash reproduction from the pinned fits, and the lookups on both choice jobs, and
     they need only choice-block data and run 1's file.
  2. Write `fo_opening_judged.csv` (sections `level` to `beside`, its manifest) as soon as stage C's frame is complete,
     before `stage_C_scorecard` is authorised.
  A scorecard failure then costs only the scorecard. The computation stays after stage C, as section 13 orders.

**W2. Floor (iii)'s state-to-gate mapping is untested.** `fo_opening.py` `_index_class` and `gate_campaign`.
- *Evidence.* The placebo gate test (`tests/fo_gate_placebo_synthetic.py`) draws its flags directly per gate block and
  holds the wrapper to them by `(historical_day, trade_index)`. That certifies the wrapper's index mode on the gate:
  both arms, the worker route, a misaligned set caught, a misfit refused. It is what floor (iii) needs **of the
  wrapper**. But floor (iii) builds its flags differently: from the pick's state through `offer_ids_of(trades, days,
  gf.gate_blocks(...))`. No test holds that mapping to the state.
- *What it lets go wrong.* If the gate's blocks order or drop trades differently from U1's, floor (iii) would run a
  design waiting for the wrong offers, and nothing would refuse.
- *Change.* Record the design's floor-(iii) gate call with `GateRecorder`, with offer ids given (Q-70 shows recording
  is bit-identical). Refuse unless every in-wait opening's **offer id** is in the pick's state set and every declined
  offer's offer id is out of it. Hold the same check in the synthetic run 2 through the same `_index_class` route.
