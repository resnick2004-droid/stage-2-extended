## Refusal items

1. **The size count's factors do not describe the checks the text declares** (`prereg/H3_three_way.md:160-164`; the
   test fixes the same factors at `tests/test_h3_draft.py:291-297`).
   - l.160-162 say "per part (A1, A2), 3 null classes (the antithetic twin, the disjoint sets, the exact-centred pair) x
     3 bounds x 3 feasible levels = 27 pooled counts a part".
   - But A1 is "the same-design nulls on placeholder composites (`P_B` ... and a clipped toy composite)" and A2 is "the
     exact-centred toy null" (l.296-298). The note's 6.1 says the same, and so do Appendix A (A1 arms = 3, A2 arms = 2,
     l.453-454) and `extended/three_way_h3a.py` l.11-14 (A1 fixes both composites; A2 fixes only its pair).
   - So A1 has 2 null classes, not 3, and it runs on 2 composites, a factor the size product leaves out. A1's own
     product is 2 x 2 x 3 x 3 = 36, not 27.
   - A2 has 1 null class, and **its composite(s) are declared nowhere**: 1 x c x 3 x 3 is 18 if c = 2, 9 if c = 1.
   - The totals 54 and 1080 hold only if A2 runs both composites (36 + 18). If it runs `P_B` alone they are 45 and 900.
   - The stop reads "the 54 pooled size counts" (l.301-302), but the text never says which 54 they are. Bonferroni at
     0.05 / 54 keeps its 0.05 guarantee only if the true number is at most 54. The text does not pin that, for example
     by saying which schedules the same-design nulls run on.
   - **Needed:** the size checks written per part with the factors that run, quoting the template's form, "k_cells =
     <the product of the cells' factors, written as a product and a number>; every cell is counted". That is A1's null
     classes x composites (x schedules, if more than A1's design) x bounds x levels, and A2's the same, A2's composites
     named. Then the pooled total, the per-history total and the stop's divisor written to match.
   - **Class: form.** No rule changes if A2 is declared on both composites (36 + 18 = 54, divisor unchanged). If it is
     declared on `P_B` alone, the author either keeps 0.05 / 54 (valid, conservative) or writes 0.05 / 45. Either is
     fixed before any outcome. The lead cannot cure this in the pin row alone: the pinned words would then misstate the
     checks that run, and the auditor would find the deviation. It needs a text edit before the pin, limited to
     section 8's size bullet, section 11's stop sentence if the divisor moves, and the test's factors. It is not a
     re-declaration of H3's substance.
2. **Section 14 reopens which counts the stop reads** (`prereg/H3_three_way.md:329-331`).
   - "A pass: every size count shows no laxity at the feasible levels". The per-history counts are size counts too.
   - Section 11 (l.305-306) says they "never stop anything".
   - Read literally, section 14 makes all 1080 per-history counts pass conditions, at 2.5 % per count under E-052's
     criterion. That is exactly the after-the-fact choice c2-3 closed.
   - **Needed:** "every pooled size count shows no laxity at 0.05 / 54 (section 11)", or the same in other words.
   - **Class: form.** The lead could rule that section 11 governs. But it is one phrase, and it is better fixed in the
     same edit as item 1 so the pinned text has one reading.
3. **The build's only laxity function contradicts the declared stop, and the text does not say what code computes the
   stop** (`extended/three_way_stats.py:368-373` at 4c07026; `prereg/H3_three_way.md:25`, `:301-306`, `:403-408`).
   - `three_way_stats.size_label` labels a count "lax" when the two-sided 95 % Clopper-Pearson lower limit exceeds the
     level. That is E-052's criterion, about 2.5 % per count, the note's 2.6.
   - Section 11 declares a one-sided lower limit at confidence 1 - 0.05 / 54. No function at the build commit computes
     that.
   - The red team's review confirms that H3-A's report code is not built ("What I could not check").
   - A driver written after the pin that calls the build's `size_label` would apply the stop this text has just
     replaced. The family-wise false-stop rate on 54 counts would then be far above 0.05.
   - **Needed:** one of these two:
     - (a) the pin row records that H3-A's report code is built after the pin, applies section 11's one-sided limit to
       the pooled counts only, uses `size_label` only as a reported label beside the stop (or not at all), and has a
       red-team diff check and its own tests before H3-A runs;
     - (b) the text says the same in section 17.
   - **Class: form.** It can be ruled in the pin row without a new declaration. The text's rule is unambiguous; only
     the code that will compute it is missing.
