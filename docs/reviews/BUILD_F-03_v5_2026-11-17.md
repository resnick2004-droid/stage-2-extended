## Y1: the wrapper

`run2` now wraps `_run2`. `ctx.stage_c_started` is set right after K0 on the judged C1 counts, which is stage C's first
line. Any exception (re-raised after writing), and any non-zero return, then calls `_partial_judged`. That writes the
judged file with the rows computed so far and a `partial` verdict row, unless the full file was already written. Can
anything slip past?
- **Before `stage_c_started`.** The pre-checks, the `stage_C_states` read and the states' refusals run here. Nothing is
  written, which is right: no line has been computed, and the only judged data read are bars and day kinds, with no
  outcome.
- **After the file is written.** `_partial_judged` returns when `judged_path` is set, so a scorecard refusal or failure
  leaves the full file untouched and writes no second verdict.
- **The rows reach the wrapper.** `ctx.stage_c_rows` is the list `out` itself, and `_run2` only extends it in place;
  I found no rebinding. So every line and K0 form computed before a stop reaches the partial file.
- `BaseException` also catches an operator's interrupt, which then leaves a partial record. That is acceptable and
  consistent with the failure protocol.
- One edge: a failure inside `write_judged` itself, after the verdict row has been appended, would add a second
  (partial) verdict row on the retry. That is harmless, since the write would fail again.

**The status rule against "a fail of any line closes the family".**
- `partial_status` reads `CLOSED` when C1, C1-close or C3 has `passes` False, or C2 has `passes_bar` False. That is
  the section 12 rule.
- **Z1 (minor).** Floors are lines too ("every line of stage C and every floor holds"). Floor (i) is computed before
  floor (iii)'s gate call (`f1`, `f1b`), but appended to `out` only after W2, so a W2 refusal with floor (i) failed
  reads `not formed`. *Change:* append floor (i)'s rows before the gate call, and have `partial_status` count any
  `floor` row with `holds` False.
- **Is a lax K0 rightly CLOSED?** Yes. Section 12 says that if either judged count form is lax, "a pass is not claimed
  whatever the lines read ... and the family closes".
- **Z2 (minor).** The declared verdict for that case is the phrase "not claimed: the judged counts make cons lax", and
  the full path already uses it. *Change:* the partial path should write the same phrase when only K0 decides, and
  `CLOSED` naming both when a line has also failed.

**The test.** `tests/fo_run2_w1.py` (c) plants a W2 mismatch after C1, C1-close, C3, C2 and both K0 forms. It asserts
the partial file with its manifest, those lines, one partial verdict row whose status matches the rule, and no
scorecard authorisation.
- **Z3 (minor).** The exception path (write, then re-raise) is not exercised. *Change:* plant an exception in stage C,
  for example in the gate call, and assert that the partial file exists and the exception propagates.
