## B. Findings

### MINOR (before the reading's run; most easily before merge)

**L1. The waits do not cover the identities' own scripts, nor the package root.** `scripts/pp_reading.py:65-86`.

- **Evidence.**
  - `WAITS` covers the modules each identity exercises, but for none of the five waits the script or test that *is* the
    identity:
    - RD-02's own identity omits `identity/pp_identity.py`;
    - Q-80 omits `identity/gate_identity.py` (and its comparator, `identity/stage2_identity.py`);
    - Q-93 omits `identity/user_beside_identity.py`;
    - Q-101 omits `identity/replay_records_identity.py` (with `user_beside_identity.py`, which it imports);
    - `t10w2` omits `tests/pp_synthetic.py`, whose `section_t10w2` is the check, and `identity/gate_identity.py`, whose
      `syn_kwargs`/`syn_blocks` are its gate fixture.
  - None covers `extended/__init__.py`, which chooses the vendored tree and the thread count for every identity.
  - D.1 shows the consequence with Q-110's own `held()`, on the declared list for RD-02's own identity: the script is
    edited after its token's commit, and the wait is **still met**. With the script added to the list, it is not.
  - 8.1 and 14 make step 1 "`identity/pp_identity.py` ... from a clean checkout of the reading's commit". E-104 meets a
    wait only with "the identity's declared covered files unchanged". RD-01's runner covers each identity's own script
    and the package root in a `BASE` (`rd01_reading.py:180-192`).
- **What it allows.** An identity script weakened, or merely changed, after its token, followed by a reading that waits
  on a certificate of a different instrument. One example: a comparison loosened in `pp_identity.py`, or an arm dropped
  from `gate_identity.py`, after the heavy run.
- **Remedy.**
  - Add to each wait its own script, the comparator modules it imports from `identity/`, and `extended/__init__.py`:
    - RD-02's own identity: `identity/pp_identity.py`;
    - Q-80: `identity/gate_identity.py` and `identity/stage2_identity.py`;
    - Q-93: `identity/user_beside_identity.py` and `identity/stage2_identity.py`;
    - Q-101: `identity/replay_records_identity.py`, `identity/user_beside_identity.py` and `identity/stage2_identity.py`;
    - `t10w2`: `tests/pp_synthetic.py` and `identity/gate_identity.py`.
  - Better: declare the three shared identities' covered paths once, for both runners. RD-01 and RD-02 now list
    different paths for the same Q-80 and Q-93 tokens, so one token can meet one runner's wait and not the other's.

**L2. The E-015 limits row's words test admits a refusal, and two rows naming one column both apply.**
`extended/pp_run.py:1451-1488`.

- **Evidence.**
  - The test is two substrings, `"operator"` and `"approv"` (1478-1480).
  - D.2, on the verbatim pattern: a positional limits row whose text reads "drafted for the operator; not approved: the
    operator declined" is **admitted**.
  - A later row approving a revised bound for the same column is admitted *beside* the one it replaces, and all of them
    flag the menu.
- **What it allows.** A flag computed from a declined or superseded bound. No limits row exists today, so the menu reads
  "none approved".
- **Remedy.**
  - Refuse a limits row whose words carry a negation of approval ("not approv", "unapprov", "disapprov", "declin",
    "withdraw").
  - For each column, take the newest admitted row (or refuse two rows naming one column), and test both cases.
