## 1. Verdict: **BLOCK** (fix before merge / W42-R1 pin)

`SEARCH_CALENDAR_SHA256` in `extended/wave42.py:51` and `docs/plans/WAVE42_SETTING_RULE.md:254` **matches** `results/search_calendar.csv.manifest.json:127` and the raw bytes / git blob of `results/search_calendar.csv` on `master` (E-266) bit-for-bit, and `extended/h4_collect.py` is pure (no engine/bar/held-out imports) and round-trips finite float64 (including subnormals and `-0.0`) and canonical blank NaN bit-for-bit across LF, CRLF, `csv.DictWriter`, `pandas.DataFrame.to_csv`, and end-to-end `scripts/wave42_apply.py::apply`.

However, `extended/h4_collect.py` sits in `scripts/wave42_apply.py:61-63` (`IMPORTED_FILES`) and is **frozen once W42-R1 is pinned** (any post-pin fix forces a W42-R1 re-pin). Three **MATERIAL** refusal-contract gaps were proved by synthetic probes and must be fixed before merge:

1. **F1 (MATERIAL):** `w42_readings` never validates `block`, `reading`, `arm`, `VERDICT` (`denial`, `placement`, `focused_trader`), `W`, or `calendar_sha256` in `sidecar["parameters"]` — it reads the CSV and returns `BaselineReading` objects for `block="held_out"`, `block="confirmation"`, `reading="as_walked"`, `arm="worse_1"`, `W="126"`/`True`/`63`, and bogus `calendar_sha256`.

Three **MINOR** items (uncaught `UnicodeDecodeError`/`csv.Error` + double disk read, `rows_from_readings` edge-case gaps and loose CSV seed tokens, and thin test coverage) are recorded below.

## 3. Findings

### F1 — MATERIAL: `w42_readings` never validates `block`, `reading`, `arm`, `VERDICT`, `W`, or `calendar_sha256`

- **Where:** `extended/h4_collect.py:118-121, 145-149, 201-204`
- **Evidence:**
  - Lines 118-121 only check key presence (`k not in params`), never key values, for `block`, `reading`, `arm`, `denial`, `placement`, `focused_trader`, `W`, and `calendar_sha256`.
  - Lines 145-146 read `block = params["block"]` and `reading = params["reading"]` and construct `W.BaselineReading(name=b, block=block, reading=reading, ...)` at line 202 without checking `block == W.BLOCK` or `reading == W.READING`.
  - Synthetic probes confirmed `w42_readings` **accepts** (opens and parses the entire CSV, then returns `BaselineReading` dicts) for every one of:
    - `block="held_out"`, `block="confirmation"`, `block=""`, `block=None`, `block=123` (with matching `readings_sha256`);
    - `reading="as_walked"`, `reading="as_traded"`, `reading=""`, `reading=None`;
    - `arm="worse_1"`, `denial=0.5`, `placement="on"`, `focused_trader="on"`;
    - `W=63`, `W="126"`, `W=True`;
    - `calendar_sha256="not-a-valid-sha"` and `calendar_sha256="0"*64` (mismatching `W.calendar_digest(starts)`).
  - Even when called via `scripts/wave42_apply.py:239-240`, `w42_readings` parses the whole CSV before `setting_rule._validate` rejects these fields; when called standalone (e.g. by H4's auditor re-derivation or Wave 4.1), held-out/confirmation/stress-arm/as-walked readings are returned unrefused, contradicting `extended/h4_collect.py:4` ("never touches the held-out years") and W42-R1 section 1.5 ("The held-out guard runs first").
- **Remedy:** Before opening/reading the CSV, validate and refuse with `H4CollectRefused` unless:
  - `params["block"] == W.BLOCK` (first — held-out guard);
  - `params["reading"] == W.READING`;
  - `params["arm"] == W.ARM`;
  - for each `k, v` in `W.VERDICT.items()`: `params[k] == v` and (for numeric `v`) `not isinstance(params[k], bool)`;
  - `type(params["W"]) is int and params["W"] == W.W`;
  - `isinstance(params["calendar_sha256"], str) and params["calendar_sha256"] == W.calendar_digest(starts)`.
  Add refusal tests in `tests/test_h4_collect.py` for each check.

### F2 — MATERIAL: `_parse_cell` silently accepts literal `"nan"`/`"NaN"` strings; `rows_from_readings` silently serialises `inf`/`-inf`

- **Where:** `extended/h4_collect.py:50-60` (`_parse_cell`) and `extended/h4_collect.py:94-95` (`rows_from_readings`)
- **Evidence:**
  - `_parse_cell` maps blank `s == ""` to `float("nan")` (lines 52-53), converts non-blank text via `val = float(s)` (line 55), and then only checks `if math.isinf(val):` (line 58).
  - Synthetic probes confirmed CSV cells containing `"nan"`, `"NaN"`, `"-nan"`, and `"+NaN"` are silently **accepted** as `np.float64(nan)`, violating the module contract (`extended/h4_collect.py:8-9, 16`: canonical blank `""` for NaN, finite float64 otherwise) and failing to refuse non-blank non-finite literals.
  - Conversely, `rows_from_readings` (lines 94-95) writes `"" if math.isnan(v) else repr(v)` without checking `math.isinf(v)`. Synthetic probe confirmed `np.inf` is silently written as `"inf"`, producing a CSV that `w42_readings` refuses.
- **Remedy:**
  - Change `extended/h4_collect.py:58` from `if math.isinf(val):` to `if not math.isfinite(val):` (with message indicating non-finite value refused).
  - In `rows_from_readings` (around line 94), raise `_refuse(...)` when `math.isinf(v)` (or check `np.isinf(mat).any()` per matrix).
  - Add tests for literal `"nan"`/`"NaN"` refusal in `w42_readings` and `inf`/`-inf` refusal in `rows_from_readings`.

### F3 — MATERIAL: Missing ISO-date validation on `starts` and loose `int()` coercion on `seeds`

- **Where:** `extended/h4_collect.py:132-143`
- **Evidence:**
  - Lines 132-137 convert `starts = tuple(str(d) for d in starts_raw)` and check only string comparison `W.SEARCH_FIRST <= d <= W.SEARCH_LAST`. There is no `isinstance(d, str)` check, no `YYYY-MM-DD` format check, and no calendar validity check (`datetime.date.fromisoformat`).
    - Synthetic probes confirmed `w42_readings` **accepts**: `("2020-01-02", "2020-99-99", "2021-01-04")`, `("2020-01-02", "2021", "2022-not-a-date")`, `(2021, 2022, 2023)`, and `("2020-02-30", "2020-02-31", "2020-03-01")`.
  - Lines 138-143 coerce `seeds = tuple(int(c) for c in seeds_raw)` and exclude only `bool`.
    - Synthetic probes confirmed `w42_readings` **accepts** `[0.0, 1.0, 2.0, 3.0]`, `[0.9, 1.9, 2.9, 3.9]`, and `["0", "1", "2", "3"]`, silently truncating/coercing them to `(0, 1, 2, 3)`. Notably, `[0.9, 1.9, 2.9, 3.9]` would even slip past `extended/wave42.py:259` (`[int(s) for s in man["seeds"]]`).
- **Remedy:**
  - Require every element of `starts_raw` to be `str`, match `r"\d{4}-\d{2}-\d{2}"`, and parse with `datetime.date.fromisoformat(d)` before range/order checks.
  - Require every element of `seeds_raw` to satisfy `isinstance(c, int) and not isinstance(c, bool)` (refusing floats and strings).
  - Add unit tests for non-ISO starts, invalid calendar dates, integer starts, and float/string seeds.

### F4 — MINOR: Corrupt CSVs leak raw `UnicodeDecodeError` / `csv.Error`, and `csv_path` is read twice

- **Where:** `extended/h4_collect.py:111, 155-156, 174`
- **Evidence:**
  - Synthetic probe confirmed that a file with invalid UTF-8 bytes (and matching `sidecar["sha256"]`) raises uncaught `UnicodeDecodeError` instead of `H4CollectRefused`, contradicting line 19 ("Any violation raises `H4CollectRefused` before returning"). Similarly, `csv.Error` (e.g. a field exceeding `csv.field_size_limit`) is not wrapped.
  - Line 111 reads the full file via `_sha256_file(path)` (`path.read_bytes()`), then line 155 opens and reads `path` a second time from disk instead of parsing the already-verified byte buffer via `io.StringIO` (unlike `extended/search_calendar.py:322-330` and `scripts/wave42_apply.py:216-220`), creating redundant I/O and a small TOCTOU window between hash and parse.
- **Remedy:** Read `raw = path.read_bytes()` once (catching `OSError`), hash `raw`, decode `raw.decode("utf-8")` catching `UnicodeDecodeError -> raise _refuse(...)`, and iterate `csv.DictReader(io.StringIO(text, newline=""))` catching `csv.Error -> raise _refuse(...)`.

### F5 — MINOR: `rows_from_readings` edge-case gaps and loose CSV seed parsing

- **Where:** `extended/h4_collect.py:63-97, 183-186`
- **Evidence:**
  - `rows_from_readings(r, extra_keys=("seed",))` emits duplicate `"seed"` in `cols` (`cols.count("seed") == 2`) and overwrites `rec["seed"]` with `repr(float)` at line 95, breaking CSV output so `w42_readings` refuses it (`duplicate column names`).
  - `rows_from_readings` does not check that all four baselines share the same `block` and `reading` (silently dropping mixed values on serialisation), and `np.asarray(..., dtype=np.float64)` at line 86 raises raw `ValueError`/`TypeError` on non-numeric entries instead of `H4CollectRefused`.
  - In `w42_readings` line 184, `int(row["seed"].strip())` accepts non-canonical CSV seed tokens `"+0"`, `"00"`, `"-0"`, and `"0_0"`.
- **Remedy:** Refuse `set(extra_keys) & set(ID_COLUMNS)`, check uniform `block`/`reading` across baselines (or equal to `W.BLOCK`/`W.READING`), wrap array conversion errors in `H4CollectRefused`, and require canonical non-negative integer strings (`re.fullmatch(r"0|[1-9]\d*", raw_seed)`) for CSV `seed`.

### F6 — MINOR: Thin refusal and integration coverage in `tests/test_h4_collect.py`

- **Where:** `tests/test_h4_collect.py:1-145`
- **Evidence:** The test file has 5 tests and omits coverage for F1-F5 as well as CRLF and `pandas.DataFrame.to_csv` round-trips, missing `parameters` / missing `H4_MANIFEST_KEYS`, unknown baseline/start/seed, empty/ragged/duplicate-header CSVs, extra columns (unregistered vs `extra_keys`), `rows_from_readings` refusals, and an end-to-end `scripts/wave42_apply.py::apply` test using the real `extended.h4_collect.w42_readings` (since `tests/test_wave42_apply.py:85-87` uses a mock adapter).
- **Remedy:** Expand `tests/test_h4_collect.py` to cover all refusal paths above plus a CRLF/`pandas` round-trip and an end-to-end `wave42_apply.apply` test with the real adapter.
