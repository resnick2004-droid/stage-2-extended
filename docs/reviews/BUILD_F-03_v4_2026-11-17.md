## 1. W1

- **The refusing checks come first.** `choice_precheck` runs before `ctx.authorise("stage_C_states")`. It does all
  three of the choice-block beside's refusing checks: each pinned fold's hash, the choice block's states recomputed
  from the pinned fits against run 1's `states_sha256`, and the lookup on every start of both arms' choice jobs. It
  reads only choice-block data and run 1's file. The choice span it builds (`ctx.span`) is the one stage C used before,
  over the same dates.
- **`choice_problems` at the scorecard stage is harmless.** It checks the extra P against the card's P on rows the
  replays make, so it cannot run earlier. It can now refuse only the scorecard: stage C's file is already written. The
  cost of such a refusal is the scorecard's own read, which a `repeat` row can authorise again.
- **The judged file is written first.** `fo_opening_judged.csv` and its manifest are written (`Ctx.write_judged`)
  immediately after the verdict row, before `stage_C_scorecard` is authorised, and `write_stage_c` then writes only
  `fo_journey.csv`.
- **The two files' manifests.** Writing two results in one run does not mark the second `-dirty`: the vendored
  `git_commit` ignores files the process itself wrote (`note_written`, D-207).
- **The planted-failure test shows it.** `tests/fo_run2_w1.py` (b) raises at `authorise("stage_C_scorecard")`, which
  comes after the write. The test asserts:
  - the judged CSV and its manifest exist, with sections `level` to `beside` and one verdict row;
  - the authorised purposes are exactly the first three;
  - no journey file.
  Any later scorecard failure comes after the same write, so the test covers them too. Part (a) plants a bad fold hash
  and shows run 2 refusing with nothing authorised. The states-hash and lookup refusals take the same return.

## 2. W2

- **What `gate_state_problems` holds.** On a recorded campaign, by offer id, independently of the waiting class's
  flags:
  - every in-wait opening's offer (the recorder's `offer`) is in the pick's state set;
  - every declined offer's id (`offer_ids[h][j]`) is out of it;
  - every opening's recorded date equals its offer id's date.
  In run 2 it runs on floor (iii)'s own gate call, on every recorded shift (`point` and `lower_bound`). It refuses on a
  mismatch or on nothing recorded.
- **The same route as the real run.** In run 2 the class's flags come from `_index_class` (`offer_ids_of` on the gate's
  own blocks, then `flags_by_block`), and the recorder's ids come from the same `offer_ids_of` on the same `blk`.
- **Why that shared source is not circular.** Q-70's `block_offer_ids` refuses unless each block's trade count and
  entry times equal the trade table's in its stable entry-time order. A misnamed trade cannot pass that guard, so the
  ids are independently anchored. The `date` comparison adds a block-level anchor.
- **The synthetic fixture** builds its ids with `block_offer_ids` directly. It shows the check passing on both arms
  with in-wait openings and declines present, refusing a state set moved by one block, and refusing a recorder without
  ids.
- **Y4 (NOTE).** The entry-time guard applies only where a block carries `entry_t`. Floor (iii)'s blocks come from
  `gate_blocks(..., require_exits=True)`, which carries them, but say so in `gate_state_problems`, or assert it.

**The builder's two readings.**

- **Reading 1, that W2 need not see a decline.** It is literally right about my third-read wording, but the rule the
  family adopted for its identities is that they must bite (M2, E-112: A1 items 4 and 5 refuse on no declines or no
  in-wait openings), and the synthetic gate test asserts both.
  - *Why it matters on the real call.* With 500 paths, five seats and a state on about a third of offers, a design
    campaign with no decline or no in-wait opening means the wait never engaged: floor (iii) would then be read on
    P-16's campaign under the design's name.
  - **Y2.** Refuse unless each recorded arm shows at least one in-wait opening and one decline (the counts are already
    in `w2_counts`). This is minor, and goes before run 2.
- **Reading 2, that a W2 mismatch refuses before the verdict, so nothing is written.** This is not right as it stands.
  W2 runs after `stage_C_campaign` is read, and by then the run has computed C1, C1-close, C3, both judged K0 forms,
  C2 and V_line, and floor (i).
  - *What it costs.* Refusing without writing loses them. Re-reading them needs a second run 2 under a `repeat` row,
    which re-reads all four purposes.
  - *What the text allows.* "A fail of any line closes the family": where a line has already failed, the verdict is
    determined whatever floor (iii) would say.
  - **Y1 (MATERIAL, before run 2).** On a W2 mismatch, and on any refusal or exception between `stage_C_judgement`'s
    first line and the verdict row, write `fo_opening_judged.csv` with the lines and floors computed so far. Give it a
    verdict row:
    - **`CLOSED`**, naming the failed line, when any computed line or floor has failed, or when K0 makes the judged
      counts lax ("not claimed");
    - otherwise **`not formed: <the refusal>`**.
  - Then stop before the scorecard. That is the failure protocol's "a failed check stays on record". A family closed
    by a line needs no second read. A refusal that leaves the verdict open is diagnosed with its record intact.
  - One way to build it is a `try`/`finally` around stages 3 and 4 that frames and writes `out` with the verdict as far
    as it is determined.

## 3. Anything else before run 2

- **Y3 (MINOR). V_other's dollar figure** (`v_other_rows`, `V_dollars = v_line(u_place, mean_dv(c), D)`).
  - *Evidence.* It applies place (c)'s value of a won opening and the 3R conversion (D / 4) to trades at places (b),
    (d) and (e), each at its own R. Section 7.4 says V_other is valued "each at its own R"; at R, a lift of λ is
    λ / (1 + R) of win probability, and each place's win has its own value in `u_value_map.csv` (`place_values`).
  - *Change.* Price each trade by its own place's `mean_dv` (base `p16`) and its own R's conversion, summing per trade.
    Otherwise label the figure "priced at place (c) and 3R, a placeholder". This is beside, and an assumption that
    carries money, said with the verdict.

  dollars, see Y3)** are built in `cbdf6d4` and `01aedd2`; I read them in the tree.
