## MATERIAL

### F1. `pre-commit`'s F5 untracked-file check ignores `$COMMIT_INDEX`, allowing `git commit <path>` (`--only`) to record `tier=T2` for a broken tree

**Where:** `scripts/pre-commit:225-234` (specifically `:230`, after `unset GIT_INDEX_FILE` at `:148`).

```sh
if [ -n "$COMMIT_INDEX" ]; then
    UNSTAGED=$(GIT_INDEX_FILE="$COMMIT_INDEX" git diff --name-only) || refuse "..."
else
    UNSTAGED=$(git diff --name-only) || refuse "..."
fi
UNTRACKED=$(git ls-files --others --exclude-standard | grep -v -E '^[^/]+\.log$' || true)
```

Lines `:211`, `:226`, and `:265` all pass `$COMMIT_INDEX`, but `:230` does not. When git runs `git commit <path>` (git's default `--only` partial-path commit, or `git commit --amend <path>`), git builds a temporary index `$COMMIT_INDEX` from `HEAD` + `<path>` and leaves `.git/index` untouched until commit completion.

**Evidence (Probe 1).** In a synthetic repository:
1. Create `extended/helper.py` (`ONE = 1`) and stage it with `git add extended/helper.py` (now present in `.git/index`).
2. Edit `extended/core.py` to `from extended import helper; def f(): return helper.ONE`.
3. Commit only `extended/core.py` (`git commit extended/core.py -m "..."`), whose temporary index `$COMMIT_INDEX` holds `HEAD` + `extended/core.py` and omits `extended/helper.py`.
4. Exact hook checks:
   - `GIT_INDEX_FILE="$COMMIT_INDEX" git diff --name-only` -> `''` (`extended/helper.py` is not tracked in `$COMMIT_INDEX`).
   - `git ls-files --others --exclude-standard` (without `GIT_INDEX_FILE`) -> `''` (`extended/helper.py` IS staged in `.git/index`).
   - With `GIT_INDEX_FILE="$COMMIT_INDEX"` added -> `'extended/helper.py'` (caught).
5. `pytest` in the worktree passed (`1 passed`), while a clean detached checkout of `HEAD` (`git worktree add --detach ... HEAD`) failed collection with `rc=2` (`ERROR tests/test_core.py`, missing `extended/helper.py`).

**Failure it allows.** A routine `git commit <file>` beside an already-staged new module passes `pre-commit` on the worktree, writes `tier=T2` for a committed tree that cannot even import, and is then admitted by `check_verdicts` and the merge gate.

**Remedy.** Pass `GIT_INDEX_FILE="$COMMIT_INDEX"` to `git ls-files --others --exclude-standard` whenever `$COMMIT_INDEX` is non-empty, and capture `git ls-files`'s exit code separately instead of masking failures with `| grep ... || true`. Add an end-to-end test in `tests/test_fasttier_preflight.py` that stages a new module and commits only the importing file via `git commit <path>`.

### F2. `pre-commit` checks worktree/index agreement only before acquiring `fasttier_lock.py`, never after the fast tier finishes (TOCTOU)

**Where:** `scripts/pre-commit:116`, `:225-234`, `:268-291` (contrast with `scripts/fasttier_full.py:103-108`).

`pre-commit` computes `$TREE` at `:116` and checks `UNSTAGED`/`UNTRACKED` at `:225-234`, **before** calling `scripts/fasttier_lock.py run` (`:269-273`), which may wait up to 3 hours in the queue and then run the fast tier for 30–45 minutes. After `FT_RC == 0`, lines `:282-291` immediately append `$TREE\t...\ttier=T2` to `fasttier-verdicts.log` with no post-run check that the worktree still matches `$COMMIT_INDEX` or that `git write-tree` still equals `$TREE`.

**Failure it allows.** A commit starts with a clean worktree matching a broken staged `$TREE` and enters the lock queue. While waiting (or during the test run), the worktree is edited (an editor save, a script, or a fix left unstaged). Git locks the index during `git commit`, not the worktree, so pytest runs on the modified worktree and passes, `pre-commit` records `tier=T2` for the original broken `$TREE`, and git commits that broken `$TREE`. `fasttier_full.py` explicitly closed this exact window by re-checking `dirt(root)` after the run; `pre-commit` did not.

**Remedy.** Extract the dirt check into a shell function in `scripts/pre-commit` and run it both before `fasttier_lock.py` (fast fail) and again after `FT_RC == 0` (along with re-checking `git write-tree` == `$TREE`) before appending the verdict line; refuse on any post-run mismatch.

### F3. `commit-msg` runs `--merge-gate` and appends a permanent `gate` line BEFORE checking `fasttier-pending`

**Where:** `scripts/commit-msg:33-53` vs `:54-72`, and `scripts/check_verdicts.py:164-188`.

In the main tree with `MERGE_HEAD` present, `commit-msg` calls `check_verdicts.py --merge-gate` at `:52` *before* checking `<gitdir>/fasttier-pending` at `:54-72`. `merge_gate()` checks whether every tip in `MERGE_HEAD` has a T2 verdict; if so, it immediately appends `gate\t<result>\t<stamp>\ttips=<tips>` to `fasttier-verdicts.log` and returns 0.

**Evidence (Probe 2).** On a synthetic repository:
1. Branch `wt/a` has a T2 verdict on its tip.
2. On `master`, run `git merge --no-ff --no-commit wt/a`, edit `core.py` to break it (simulating a bad conflict resolution or post-merge edit), and `git add core.py` (producing `<broken_tree>`).
3. `pre-commit` runs, writes `<broken_tree>` to `.git/fasttier-pending`, and is SIGKILLed (the exact Q-161 Windows failure mode `commit-msg` exists to catch).
4. `commit-msg` invokes `merge_gate()`, which returns `None` and writes `gate\t<broken_tree>\t...\ttips=<wt/a>` to `fasttier-verdicts.log` *before* lines `:54-72` refuse on `fasttier-pending`.
5. When `<broken_tree>` is subsequently committed (e.g., `--no-verify` or recovery), `check_verdicts.unverified_first_parent(["<base>..master"])` returns `[]` (reports `master` clean).

**Failure it allows.** A killed `pre-commit` on a conflicted or `--no-commit` merge of a verified branch permanently stamps the unverified conflict-resolved tree with a `gate` line in `fasttier-verdicts.log`, hiding it from `check_verdicts --first-parent`.

**Remedy.** Run the `fasttier-pending` check (`:54-72`) *before* the `--merge-gate` block (`:33-53`) in `scripts/commit-msg`, and inside `merge_gate()` refuse without writing a gate line if `<gitdir>/fasttier-pending` names `result` while `result not in have`. Add a regression test in `tests/test_git_hook_verdicts.py`.

### F4. `fasttier_xdist` samples `available_gb()` and `fast_tiers_beside()` BEFORE pre-flight runs, allowing worker oversubscription

**Where:** `scripts/fasttier_xdist.py:539-540` and `:421-445`.

In `main()` (`:539`), `available_gb()` and `fast_tiers_beside()` are evaluated as plain values and passed into `run(...)` *before* `run()` executes the serial pre-flight (`:421-428`). While the pre-flight runs (minutes of serial pytest over 16+ guard and direct test files), this slot's record in `fasttier_lock` still reports `workers=1` (`record(n)` is not called until `:445`).

**Evidence (Probe 4).** `run()` takes scalar `available: float | None` and `beside: list[int] | None` and never re-reads them after pre-flight: with `available=12.0, beside=[]` sampled before pre-flight, `run()` chose `n=4` after pre-flight even if another slot started at `workers=3` and free RAM dropped to `2.0 GB` during pre-flight (for which `choose_workers(2.0, beside_gb=slot_reserve_gb(3))` returns `n=1`).

**Failure it allows.** Slot 1 enters at 12 GB free and runs a multi-minute pre-flight at `workers=1`. Slot 2 arrives, sees Slot 1 at `workers=1`, gets admitted, and picks `n=3`. Slot 1 finishes pre-flight, uses its stale pre-preflight snapshot (`beside=[]`), and launches `n=4` — 7 workers running concurrently, recreating the Q-155/Q-193 memory-exhaustion condition that `slot_reserve_gb` and `fast_tiers_beside` were built to prevent.

**Remedy.** Sample `available_gb()` and `fast_tiers_beside()` *after* pre-flight completes (right before `choose_workers` in `run()`, e.g., passing zero-arg callables or sampling inside `run()` when omitted). Add a unit test in `tests/test_fasttier_xdist.py` where memory/beside changes during the pre-flight call and assert `choose_workers` sees the post-preflight values.

### F5. `premerge_check.dirty_checked_files` ignores untracked files, and HEAD's checker still runs the merge result's check scripts/tests

**Where:** `scripts/premerge_check.py:73-82`, `:113-128`, `:133-142`.

- **Evidence (Probe 5):** Adding an untracked `tests/conftest.py` leaves `dirty_checked_files(r)` returning `[]` because it runs only `git diff --name-only -- *paths`, not `git ls-files --others --exclude-standard -- *paths`. An untracked `tests/conftest.py` or untracked `prereg/<name>.md` in the worktree can therefore alter `pre-merge-commit`'s pytest checks without being part of the merge commit.
- **Scope of HEAD's checker:** Running HEAD's `premerge_check.py` stops a branch from disarming `premerge_check.py` itself, but Checks 1–4 still execute the merge result's `scripts/vendor_stage2.py`, `extended/reader.py`, `tests/test_declarations_fixed.py`, and `tests/test_identity_tokens.py` (unlike `commit-msg`'s HEAD `check_verdicts.py`, which is self-contained and calls only `git`).
- **Remedy:** Include `git ls-files --others --exclude-standard -- *paths` in `dirty_checked_files`, and document (or refuse/flag) when a clean merge modifies the four check files themselves.

### F7. Minor edge cases in hook shell guards, installer, verdict parsing, and plant test

- `scripts/pre-commit:230`: `UNTRACKED=$(git ls-files ... | grep -v -E '^[^/]+\.log$' || true)` silently swallows a `git ls-files` failure (unlike `UNSTAGED`'s `|| refuse`). Also `git rm --cached` on a tracked file matching `.gitignore` or `^[^/]+\.log$` leaves the file on disk unseen by both `UNSTAGED` and `UNTRACKED` (Probe 6f).
- `scripts/commit-msg:23,32,65` & `scripts/post-commit:27`: `commit-msg:23` exits 0 if `git rev-parse --absolute-git-dir` fails, and `:32` silently skips the merge gate if `--git-common-dir` fails. Both `commit-msg:65` and `post-commit:27` grep `^$tree\t` without excluding non-T2 `tier=` lines (legacy T0/T1 lines in an existing log would still match). In `scripts/check_verdicts.py:63`, `startswith("tier=")` is case-sensitive (`Tier=T0` returns `True`, Probe 7).
- `scripts/install_hooks.py:166`: `git config branch.master.mergeOptions --no-ff` fails (`rc=1`) if `branch.master.mergeOptions` is already multi-valued (Probe 3e); `--replace-all` makes it idempotent. Docstrings in `scripts/pre-merge-commit:16` and `scripts/premerge_check.py:29` still say `merge.ff=false` rather than `branch.master.mergeOptions=--no-ff`.
- `tests/test_fasttier_plants.py:72`: `_run()` runs `pytest <nodeid>` without `-m "not slow and not heavy"`, so it does not assert that the two target tests remain in the fast tier (verified via `--collect-only`: both currently are).
