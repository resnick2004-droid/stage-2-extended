## 2. New findings

### MATERIAL (each before run 1)

**V1. The heavy T-3 (`--t3`) cannot fail.** `scripts/fo_opening.py` 1265-1336 (`T3Ctx`, `t3`).
- *Evidence.* `T3Ctx` replaces judged-block rows only in the frames that its `grid` and `span` seams receive. Those
  seams request `CHOICE_START..CHOICE_END`, so they never hold a judged row: `m.any()` is always False and `replaced`
  is always 0. The comparison is then run 1 against itself.
- *What it lets go wrong.* A path that reached judged-block data some other way would leave the seams untouched and
  T-3 would still print HOLDS. Examples: a vendored loader such as `atlas_a3.bar_arrays` or `propedge.data.bars`, an
  atlas table, or a cache. The declared T-3 replaces the judged block in the store, so that any path sees the
  replacement. Separately, the synthetic proxy (`tests/fo_t3_synthetic.py`) is sound: two generated stores read
  through the reader.
- *Change.* The licensed store cannot be copied (E-002), so replace in memory below every loader: wrap the parquet
  reads of `data/bars` and `data/atlas` used by both `extended/reader.py` and the vendored loaders, so that every row
  dated from 2024-01-02 is replaced by the test key's walk and counted.
  - Make T-3 refuse unless the wrapper was entered at least once, which proves it is wired.
  - Print the count of judged rows replaced. Zero is the evidence that run 1 reaches no judged row; any other count is
    already a failure.
  - Refuse unless the compared file's manifest commit is HEAD.

**V2. A10's consequence has never run inside run 1.** `fo_opening.py` 680-694; `tests/fo_run1_synthetic.py`.
- *Evidence.* No synthetic run 1 flags A10 (`killed == {}`, 24 A10 rows). The consequence is tested only on toy
  layouts (`tests/test_family_o_consequence.py`) with kinds n and b and a few hundred sessions.
- *What it lets go wrong.* The branch M1 was about runs for the first time hours into the real run 1, on a real layout
  of about 754 sessions carrying FOMC and early-close kinds (V3). Any defect there (a crash, a wrong row, a kill not
  recorded) would force a second run 1 after A10 has flagged a known class, the situation E-112 ruled to prevent.
- *Change.*
  - Add to the synthetic run 1 a variant that flags one deciding class: a seam on `ST.a10` or a toy whose `cons` is
    lax. Assert the consequence's rows, its verdict row, the kill (or the stay), and that stage B continues.
  - Run `a10_consequence` once on a toy of the real size and kind mix, at a few selections, to show it runs and to
    measure its time per B2 run.
  - Compute the consequence once per class: s1 and s2 both decide by `window`, and today it runs twice.

**V3. B2 runs one bootstrap per day kind of A1's table, not the declared two.** `opening_stats.py`
`b2_replicate_sums` (`for kind in np.unique(inp.judged_kind)`).
- *Evidence.* Section 11 item 2 declares "two stationary bootstraps ... normal days and report days". Run 2 and A10's
  consequence pass layouts over every session of the calendar. A1's kinds are n, b, o (FOMC), e (early close) and x
  (no bar by the flatten; `atlas_walk._kind`). So the loop bootstraps each kind present, and raises
  `ValueError("B2: no choice session of day kind ...")` when the target holds a kind the source lacks.
- *What it lets go wrong.* The values are unaffected, since sessions of other kinds carry no weight, but the random
  stream differs from the declared two-bootstrap form. A kind present on the judged block and absent from 2021-2023
  would raise after `stage_C_judgement` is ledgered (C1) or after `stage_C_campaign` (C2), spending the read. In run
  1, a kind present in 2023 and absent from 2021-2022 would raise inside A10's consequence.
- *Change.* Bootstrap only kinds n and b, each to its own count, and leave sessions of every other kind empty. Fix this
  before T-10 runs, and before any B2 runs on data.
